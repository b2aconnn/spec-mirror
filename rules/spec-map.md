# 명세 지도 작성 규칙

명세 지도는 프로젝트의 **기능 목록과 진행 순서**입니다. 프로젝트 전체를 명세로 옮길 때, 한 파일에 모두 쓰지 않고 기능마다 명세 폴더를 나누기 위해 씁니다.

- 위치: `<specRoot>/README.md` (기본 `docs/spec/README.md`). GitHub에서 명세 폴더를 열면 바로 보입니다.
- 지도에는 **기능 명세만** 적습니다. 버그 명세는 고치고 나면 끝나는 작업이라 적지 않습니다.
- 진행 상태는 적지 않습니다. 상태는 `spec-mirror map` · `/spec-mirror:status`가 승인 기록에서 계산합니다. 손으로 적으면 금방 틀립니다.
- 정답 예제: `examples/README.md`

## 형식

~~~markdown
# Spec Map

## Overview

<프로젝트가 무엇이고, 이 지도가 어떤 범위의 코드를 명세로 옮기는지 2~4문장>

## Features

| 순서 | 기능 | 범위 | 진입점 | 관련 기능 |
|---|---|---|---|---|
| 1 | [payment-confirm](payment-confirm/) | 결제 승인, 결과 확인, 대사 | 결제 승인 요청, 대사 배치 | — |
| 2 | [order](order/) | 주문 접수 · 조회 · 취소 · 만료 | 주문 요청 5개, 기한 만료 배치 | payment-confirm |

## Out of Scope

- <명세로 옮기지 않는 코드와 이유>
~~~

| 열 | 쓰는 것 |
|---|---|
| 순서 | 진행할 순서. 1부터 연속 |
| 기능 | `[<기능>](<기능>/)` 링크. 기능 이름은 명세 폴더 이름이고 영문 소문자 · 숫자 · 하이픈 |
| 범위 | 이 기능이 다루는 유스케이스. 각 유스케이스가 그 기능 requirements의 Requirement가 됩니다 |
| 진입점 | 요청 · 배치 · 이벤트를 도메인 말로. 코드 위치는 그 기능의 design에 씁니다 |
| 관련 기능 | 이 기능이 결과를 주거나 받는 다른 기능. 없으면 `—` |

## 기능을 나누는 기준

1. **같은 대상을 같은 규칙으로 다루는 유스케이스를 한 기능으로 묶습니다.** 예: 주문 접수 · 조회 · 취소 · 만료는 모두 주문의 상태 규칙을 따르므로 `order` 하나입니다.
2. **Requirement 하나 = 유스케이스(진입점) 하나**입니다. 요청 하나, 배치 하나, 이벤트 처리 하나가 각각 Requirement입니다. 따라 바뀌는 것과 상태 일관성은 별도 Requirement로 둘 수 있습니다.
3. **크기**: 기능 하나에 Requirement 10개, 기준 100개 정도까지입니다. 넘으면 나눕니다. 사람이 한 번에 리뷰하고 승인할 수 있는 크기입니다.
4. **기능 사이의 경계**: 한 기능의 결과로 다른 기능의 상태가 따라 바뀌면, 바뀌는 쪽 기능에 "따라 바뀌는" Requirement를 두고 결과를 주는 쪽은 `<기능> N.M`으로 참조합니다. 같은 내용을 두 기능에 쓰지 않습니다.
5. **기술 공통 코드(설정, 공통 에러 처리, 유틸)는 기능이 아닙니다.** 그것을 쓰는 기능의 design에 적거나 Out of Scope에 둡니다.

## 순서를 정하는 기준

1. 다른 기능이 참조하는 기능을 먼저 합니다. 참조하는 쪽이 `<기능> N.M`을 쓸 수 있게 하기 위해서입니다.
2. 같은 조건이면 자주 바뀌거나 장애가 잦은 기능을 먼저 합니다. 명세의 효과가 가장 큰 곳입니다.

## 기능 사이 참조

다른 기능 명세의 기준은 `<기능> N.M`으로 씁니다. 예: `payment-confirm 6.21에 따라 결제 완료`. 숫자만 쓴 `N.M`은 같은 문서의 기준입니다. 검사기는 그 기능 명세에 기준이 있는지 확인합니다(REQ018).

## 검사 규칙

| ID | 수준 | 내용 |
|---|---|---|
| MAP000 | 오류 | 채우지 않은 자리표시자 |
| MAP001 | 오류 | 첫 줄 `# Spec Map`, 섹션 Overview → Features → Out of Scope |
| MAP002 | 오류 | Features 표의 열 (순서 · 기능 · 범위 · 진입점 · 관련 기능) |
| MAP003 | 오류 | 순서 연속, 기능 링크 형식, 이름 형식, 중복, 버그 명세를 지도에 적음 |
| MAP004 | 오류 | 관련 기능이 지도에 없음 |
| MAP005 | 경고 | 지도에 없는 기능 명세 폴더 |
