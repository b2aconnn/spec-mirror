# Implementation Plan: <기능 이름>

## Overview

<기존 코드에서 옮긴 명세에 테스트와 코드 주석을 맞추는 작업이라는 것을 한두 문장으로>

코드의 동작은 바꾸지 않습니다. 기존 테스트를 기준 번호로 정리하고, 빠진 기준의 테스트를 추가하고, 분기에 `R{N}-{M}` 주석을 단 뒤 명세 동기화로 마무리합니다. 새로 쓴 테스트는 **지금 코드에서 바로 통과해야** 합니다.

## Tasks

- [ ] 1. 테스트 지원 코드 확인
  - 가짜 외부 시스템, 고정 시계, 테스트 기준 데이터가 design 05와 같은지 확인
  - _Requirements: 1.1_

- [ ] 2. <Requirement 1 이름>
  - [ ] 2.1 기존 테스트 정리: <테스트 묶음 이름>
    - 기존 테스트 이름을 `R1-M <상황>이면 <결과>다` 로 바꾸고 본문을 given / when / then 으로 나눔. 검증 내용(상태 · 에러 코드 · 메시지)은 바꾸지 않고 기준과 같은지 확인
    - _Requirements: 1.1 ~ 1.4_

  - [ ] 2.2 빠진 테스트 추가
    - 테스트가 없는 기준의 테스트를 design 05 `기준 ↔ 테스트 계층` 의 계층에 추가하고 **지금 코드에서 통과**하는지 확인
    - _Requirements: 1.2_

  - [ ] 2.3 코드 주석
    - 기준을 구현한 분기 바로 위에 `R1-M` 주석을 번호 순서대로
    - _Requirements: 1.1 ~ 1.4_

- [ ] 3. 최종 Checkpoint - 명세 동기화
  - `/spec-mirror:sync {{NAME}}` 불일치 0건
  - 모든 테스트 통과 확인
  - 코드 동작이 바뀌지 않았는지 확인 (기존 테스트 전부 통과)

## Notes

- **동작 변경 없음**: 새 테스트가 실패하면 코드를 고치지 않고 멈춥니다. 명세가 틀렸으면 requirements 를 고치고, 코드가 틀렸으면 `/spec-mirror:bugfix` 로 따로 고칩니다
- **테스트 형식**: BDD 시나리오(given / when / then)이고, 이름은 `` `R{N}-{M} <상황>이면 <결과>다` `` 입니다. 테스트 계층은 지금 코드에서 판단하는 곳을 따릅니다
