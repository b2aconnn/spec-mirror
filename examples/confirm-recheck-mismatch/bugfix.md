# Bugfix Requirements Document

## Introduction

결제 승인 결과를 알 수 없어 PG에 한 번 조회했을 때, PG의 승인 내용이 주문과 다르면 결제는 실패 처리되지만 회원에게는 PG가 거절한 것처럼 `400` `PG_REJECTED`로 응답합니다. 안내 문구에는 대조한 항목 정보(예: `amount(15000 != 14000)`)가 그대로 드러납니다.
승인 응답에서 같은 불일치가 나면 PG 승인을 취소하고 `502` `PG_RESPONSE_MISMATCH`로 응답하는 것(order 6.18)과 다르고, 회원은 실제로는 승인 취소된 결제를 "거절"로 안내받습니다.

- 관련 명세: [order requirements](../order/requirements.md) 6.18, 6.21, Open Questions 9
- 범위 밖: 대사의 처리 방식, PG 승인 취소마저 실패했을 때의 수동 처리 절차
- 원인과 고치는 방법은 [design.md](design.md)에 있습니다.

## Bug Analysis

### Current Behavior (Defect)

1.1 **결과를 알 수 없어 PG에 한 번 조회했을 때 승인 내용이 주문과 다르면, PG 승인을 취소하고 결제를 실패 처리하지만 PG가 거절한 것처럼 응답한다.**
   - 재현: 주문 금액 14,000원 결제 승인 요청 → PG 승인 결과 불명 → PG 조회 결과 승인 완료, 결제 금액 15,000원
   - PG: 승인 취소 요청 (사유 "주문 정보 불일치로 인한 자동 취소")
   - 결제: 결과 확인 중 → 결제 실패 (실패 사유 `PG_RESPONSE_MISMATCH`)
   - 에러: `400` `PG_REJECTED` (`pgCode`에 `PG_RESPONSE_MISMATCH`)
   - 메시지: "amount(15000 != 14000)"

1.2 **회원에게 보여주는 안내 문구에 대조한 항목 정보가 그대로 드러난다.**
   - 재현: 1.1과 같다. PG 조회 결과의 주문번호가 다르면 "orderId(ORD_...)", 결제 키가 다르면 "paymentKey"가 안내 문구가 된다
   - 메시지: "amount(15000 != 14000)"

### Expected Behavior (Correct)

2.1 **결과를 알 수 없어 PG에 한 번 조회했을 때 승인 내용이 주문과 다르면, 승인 응답에서 불일치가 난 때와 같이 PG 승인을 취소하고 결제 실패로 응답한다.**
   - PG: 승인 취소 요청 (사유 "주문 정보 불일치로 인한 자동 취소")
   - 결제: 결과 확인 중 → 결제 실패 (실패 사유 `PG_RESPONSE_MISMATCH`)
   - 주문: order 7.2에 따라 결제 실패
   - 에러: `502` `PG_RESPONSE_MISMATCH`
   - 메시지: "결제사 응답이 주문 정보와 일치하지 않아 결제를 취소했습니다."
   - 명세: order 6.21

2.2 **회원에게 보여주는 안내 문구에는 대조한 항목 정보를 넣지 않는다.** 대조한 항목은 운영자가 보는 기록에만 남긴다.
   - 로그: ERROR `[PG 응답 불일치] orderId={주문번호} field={다른 항목} → 승인 취소`
   - 이유: 대조 항목은 회원이 이해하거나 조치할 수 없는 내부 정보다
   - 명세: order 6.21

### Unchanged Behavior (Regression Prevention)

3.1 **승인 응답에서 대조 결과가 다르면 지금처럼 PG 승인을 취소하고 결제 실패로 응답한다.**
   - 에러: `502` `PG_RESPONSE_MISMATCH`
   - 메시지: "결제사 응답이 주문 정보와 일치하지 않아 결제를 취소했습니다."
   - 명세: order 6.18

3.2 **결과를 알 수 없어 PG에 한 번 조회했을 때 승인이 확인되고 대조 결과도 맞으면 지금처럼 승인 완료로 응답한다.**
   - 응답: `200` — 주문번호, 결제 키, 결제 상태(승인 완료), 결제 금액, 결제 수단, 승인 일시
   - 명세: order 6.21

3.3 **결과를 알 수 없어 PG에 한 번 조회했을 때 PG가 결제 실패로 확정하면 지금처럼 PG가 거절한 것으로 응답한다.**
   - 에러: `400` `PG_REJECTED` (`pgCode`는 결제 실패 사유 코드)
   - 메시지: 결제 실패 사유 그대로 (없으면 "결제가 승인되지 않았습니다.")
   - 명세: order 6.21

3.4 **한 번 조회로도 확정되지 않으면 지금처럼 결과를 확인 중이라고 응답한다.**
   - 응답: `202` `PAYMENT_RESULT_UNKNOWN`
   - 메시지: "결제 결과를 확인 중입니다. 잠시 후 결제 내역을 확인해주세요."
   - 명세: order 6.22

3.5 **대사가 같은 불일치를 확인하면 지금처럼 PG 승인을 취소하고 결제를 실패 처리한다.** 대사는 회원에게 응답하지 않으며, 다른 결제의 대사도 그대로 이어진다.
   - 결제: 결과 확인 중 → 결제 실패 (실패 사유 `PG_RESPONSE_MISMATCH`)
   - 주문: order 7.2에 따라 결제 실패
   - 명세: order 7.2
