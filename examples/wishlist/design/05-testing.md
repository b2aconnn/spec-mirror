# Technical Design Document — 테스트 전략

> [design.md](../design.md)로 돌아가기

## Testing Strategy

### 테스트 전략 개요

기준은 그 판단을 하는 계층의 테스트가 맡습니다. 이 기능은 설계 규모가 작음이라 도메인 객체 없이 서비스 하나(Transaction Script)가 판단하므로 **유닛 테스트는 없고**, 서비스는 통합, Controller는 E2E로 테스트합니다. 모든 테스트는 BDD 시나리오(given / when / then)이고, 이름은 `R{N}-{M} <상황>이면 <결과>다`, 이름과 시나리오는 도메인 용어로 정책을 씁니다.

#### 1. 테스트 계층

| 계층 | 대상 | 실제로 도는 것 | 바꾸는 것 | 테스트 묶음 |
|---|---|---|---|---|
| 유닛 | 해당 없음 — 판단이 모두 Wishlist Service에 있음 | — | — | — |
| 통합 | Wishlist Service | Service ~ H2 (MySQL 모드) | `FakeProductCatalog`, 고정 `Clock` | `WishlistServiceIntegrationTest` |
| E2E | Wishlist Controller | HTTP 요청 ~ H2 | `FakeProductCatalog`, 고정 `Clock` | `WishlistE2ETest` |

**도구:** JUnit 5 + AssertJ, `@SpringBootTest`(통합), `@SpringBootTest` + `MockMvc`(E2E). 주문 기능의 `FakeProductCatalog`(장애 스위치, 호출 횟수 카운터)와 고정 `Clock`을 그대로 씁니다.

#### 2. 기준 ↔ 테스트 계층

| 기준 | 판단 위치 | 테스트 계층 | 테스트 묶음 |
|---|---|---|---|
| 1.1, 1.8 | Wishlist Controller 찜하기 | E2E | `WishlistE2ETest` |
| 1.2 ~ 1.7 | Wishlist Service `add` | 통합 | `WishlistServiceIntegrationTest` |
| 1.9 | 유니크 제약 `(member_id, product_id)`, Wishlist Service `add` | 통합 | `WishlistServiceIntegrationTest` |
| 2.1, 2.4 | Wishlist Controller 찜 해제 | E2E | `WishlistE2ETest` |
| 2.2, 2.3, 2.5 | Wishlist Service `remove` | 통합 | `WishlistServiceIntegrationTest` |
| 3.1 | Wishlist Controller 찜 목록 | E2E | `WishlistE2ETest` |
| 3.2 ~ 3.6 | Wishlist Service `list` | 통합 | `WishlistServiceIntegrationTest` |

#### 3. 에러 ↔ E2E 시나리오

| 에러 코드 | 응답 | E2E 시나리오 |
|---|---|---|
| `WISHLIST_FULL` | `409` | `R1-3b 찜 목록이 가득 찬 회원이 상품을 담으면 100개까지 담을 수 있다고 안내받는다` |
| `PRODUCT_CATALOG_UNAVAILABLE` | `503` | `R1-5 상품 정보를 확인할 수 없으면 잠시 후 다시 담으라고 안내받는다` |
| `PRODUCT_NOT_FOUND` | `404` | `R1-6 없는 상품을 담으면 상품을 찾을 수 없다고 안내받는다` |

#### 4. 테스트 지원 코드

| 이름 | 하는 일 |
|---|---|
| `회원(n).찜한다(상품)` · `찜을_뺀다(상품)` · `찜_목록을_본다()` | 통합: Service 호출, E2E: 실제 API 호출 |
| `회원(n)이_찜한_상품이_있다(…)` | 찜 데이터 준비 |
| `상품_카탈로그.확인할_수_없다()` · `상품_카탈로그는_조회되지_않는다()` | `FakeProductCatalog` 장애 스위치 · 호출 횟수 |
| `거절된다(찜_거절_사유) { … }` | 통합: 예외 종류 · 에러 코드 · 메시지 확인 |
| `결과.안내받는다(찜_안내)` | E2E: 응답 코드 · 에러 코드 · 메시지 확인 |
| `찜_목록에_한_번만_있다(상품)` · `찜_목록에_없다(상품)` | 저장된 찜 확인 |
| `찜_거절_사유` · `찜_안내` | [에러 코드](04-error-handling.md)와 1:1인 에러 코드 · 메시지(E2E는 응답 코드 포함) 목록 |

**예시:**

```kotlin
@Test
fun `R1-3b 찜 목록에 100개가 있으면 더 담을 수 없다`() {
    // given 회원 3의 찜 목록에 상품 100개가 있다
    val 회원 = 회원(3)

    // when 회원이 아메리카노를 담으면
    // then 찜 목록이 가득 찼다는 이유로 거절된다
    거절된다(찜_거절_사유.찜_목록_가득_참) {
        회원.찜한다(아메리카노)
    }

    // and 아메리카노는 찜 목록에 없다
    회원.찜_목록에_없다(아메리카노)
}
```

#### 5. 동시성 테스트

**대상:**
- 같은 회원이 같은 상품을 동시에 10번 담기 → 찜 1건, 모두 담김 또는 이미 담김 (1.9)

**도구:**
- `ExecutorService` + `CountDownLatch`

#### 6. 테스트 기준 데이터

**고정 시각:** `2026-01-15T01:00:00Z`

**회원:**

| 회원 | 찜 | 용도 |
|---|---|---|
| 1 | 없음 | 기본 (빈 찜 목록, 첫 찜하기) |
| 2 | 99개 (상품 301 ~ 399) | 한도 경계: 하나 더 담기 가능 |
| 3 | 100개 (상품 301 ~ 400) | 한도 경계: 더 담기 불가 |
| 4 | 101 · 103 · 999 (담은 일시 00:57 · 00:59 · 00:58) | 목록 정렬, 판매 중지, 판매 종료 |

**상품 (FakeProductCatalog, 주문 기능과 같은 데이터에 더함):**

| 상품 ID | 상품명 | 판매가 | 판매 여부 | 용도 |
|---|---|---|---|---|
| 101 | 아메리카노 | 4,500 | 판매 중 | 기본 찜 |
| 103 | 시즌 한정 케이크 | 7,000 | 판매 중지 | 판매 중지도 담을 수 있음, 목록의 판매 중지 |
| 301 ~ 400 | 찜 상품 001 ~ 100 | 1,000 | 판매 중 | 한도 경계 데이터 |
| 999 | — | — | 없음 | 존재하지 않는 상품, 목록의 판매 종료 |

#### 7. 주요 테스트 시나리오

```
시나리오: R1-2 이미 찜한 상품을 다시 담으면 처음 찜이 그대로 남는다      (통합)
  Given 회원 1이 아메리카노를 00:50에 찜했다
  When  회원 1이 아메리카노를 다시 담는다
  Then  처음 찜을 돌려받는다 (담은 일시 00:50 그대로)
  And   상품 카탈로그는 조회하지 않는다

시나리오: R1-3a 찜 목록에 99개가 있으면 하나 더 담을 수 있다      (통합)
  Given 회원 2의 찜 목록에 상품 99개가 있다
  When  회원 2가 아메리카노를 담는다
  Then  찜 목록에 아메리카노가 담긴다

시나리오: R1-3b 찜 목록에 100개가 있으면 더 담을 수 없다      (통합)
  Given 회원 3의 찜 목록에 상품 100개가 있다
  When  회원 3이 아메리카노를 담으면
  Then  찜 목록이 가득 찼다는 이유로 거절된다

시나리오: R1-6 없는 상품은 담을 수 없다      (통합)
  Given 상품 카탈로그에 상품 999가 없다
  When  회원 1이 상품 999를 담으면
  Then  상품을 찾을 수 없다는 이유로 거절된다

시나리오: R2-5 찜을 빼는 동안 상품 카탈로그를 보지 않는다      (통합)
  Given 회원 1이 아메리카노를 찜했고, 상품 카탈로그를 확인할 수 없다
  When  회원 1이 아메리카노를 뺀다
  Then  아메리카노는 찜 목록에 없다
  And   상품 카탈로그는 조회하지 않는다

시나리오: R3-5 찜 목록은 최근에 담은 찜부터 보인다      (통합)
  Given 회원 4가 아메리카노(00:57) · 상품 999(00:58) · 시즌 한정 케이크(00:59)를 찜했다
  When  회원 4가 찜 목록을 본다
  Then  시즌 한정 케이크(판매 중지) → 상품 999(판매 종료) → 아메리카노(판매 중) 순서로 보인다

시나리오: R1-1 회원은 상품을 찜 목록에 담을 수 있다      (E2E)
  Given 회원 1의 찜 목록이 비어 있다
  When  회원 1이 아메리카노를 담는다
  Then  아메리카노가 담겼다고 안내받는다
```
